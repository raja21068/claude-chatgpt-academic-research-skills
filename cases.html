Worked example 1 · Idea generation

From a broad idea to a testable benchmark

A student wants to discover equations that hold when conditions change. The first idea sounds promising. A closer literature search changes what the student can claim.

The whole story in 6 pictures. Read left to right, top to bottom. The full prompts for each step are further down.

  1. 1Start with a problem

    AskWhat happens to learned equations when conditions change?

    Result3 possible questions. Limits written down: 4 weeks, one laptop.

  2. 2Pick one to test

    AskWhich question can I test with data I can get and a simple comparison?

    ResultChosen: can picking the next measurement show when an equation breaks?

  3. 3Search for the same idea⚠ Already done

    AskHas anyone already done this?

    ResultYes. Medina and White already use this idea to choose experiments.

  4. 4Be honest about what's newIdea changes

    AskWhat would a reviewer say about the closest paper?

    ResultDrop the “new method” claim. Testing it when conditions change might still be new.

  5. 5Search again for the new questionNew question

    AskHas anyone compared this fairly, with the same budget?

    ResultIf yes → stop. If no → continue. Save why the idea changed.

  6. 6Plan a small test that can failReady to test

    AskCan it beat random choice with the same number of measurements?

    ResultDecide the comparisons before running. If random choice matches it, rethink.

Lesson: finding that your idea already exists is normal. Narrow it, check again, and test the smaller question.

  1. Start with a problem and a resource limit

    Give it: Your interest, available data, time and compute. Here the student has four weeks, public examples, and a laptop.

    Prompt to send
    I'm interested in equations learned from data that may fail when conditions change. I have four weeks, a laptop, and public or simulated data. Propose three distinct questions. For each, give a falsifiable hypothesis, accessible data, a simple baseline, the main metric, and a reason the idea might fail. Mark every proposed research gap as provisional.

    Check and save: Candidate questions could compare formula recovery, identify a broken equation, or diagnose a change in regime. Keep the options whose data and baselines you can obtain. Save the shortlist and why you dropped the others.

  2. Score the shortlist and pick one idea to investigate

    Give it: The three candidate briefs and the papers you have checked so far.

    Prompt to send
    Apply the Phase 10 Idea Scorecard to these candidates. Give the basis for each score. Mark novelty and gap evidence as provisional where coverage is thin. Rank the ideas for feasibility and list the one question that would most change each ranking.

    Check and save: The student picks “Can we choose measurements that expose when a learned equation breaks?” It has a plausible small test. The score is a triage decision. Save the scorecard with the literature doubts attached. Open the Phase 10 rubric ↗

  3. Search for work that could defeat the claim

    Give it: A one-sentence novelty claim and search terms such as active learning symbolic regression, query by committee equations, and equation extrapolation benchmark.

    Prompt to send
    Find papers that could make my idea less novel. Search for the mechanism under different names and in adjacent areas. For each close paper, give the source link, the passage or experiment you checked, the overlap, and what remains uncertain. Start with Phase 11. If browsing is unavailable, give searches I can run myself.

    Check and save: Existing work already uses disagreement among candidate symbolic equations to select new experiments. Open the source before updating the claim. Keep a log of the queries and what each paper actually supports. Medina and White, Active Learning in Symbolic Regression ↗

  4. Build the novelty matrix and invite a skeptical review

    Give it: The idea, the closest verified papers, and your provisional evaluation plan.

    Prompt to send
    Build a Phase 12 matrix comparing my proposal with the closest studies on what is selected, what the experiments test, and which baselines are used. Mark uncertain cells. Then do Phase 13: identify the strongest reason a skeptical reviewer would reject this version and say what evidence could change that view.
    Two example rows from the novelty matrix
    Proposed contributionWhat the cited study establishesDecision
    Select points using equation disagreementIt already uses a committee of candidate equations to propose experiments.Drop this as a novelty claim.
    Compare how quickly methods expose wrong equations under shiftThe abstract emphasizes rediscovering known equations. This comparison still needs a targeted literature search.Keep as a candidate question only.

    Check and save: Record the objection and how it changes the project. Open Phase 12 · Open Phase 13

  5. Reframe the question and run the novelty checks again

    Give it: The rejected algorithm claim, the matrix, and the narrower proposal.

    Prompt to send
    We dropped the claim that choosing points by equation disagreement is new. The revised question is whether existing methods detect an incorrect equation faster after a regime change at the same measurement budget. Search for evaluations with this outcome and comparison. Give the strongest overlap, then recommend stop, narrow, or pilot with reasons.

    Check and save: Stop the novel-algorithm claim. Continue with the benchmark only if a targeted search leaves a defensible evaluation gap. Save the revised question and the reason you changed it.

  6. Plan a pilot that can make you stop

    Give it: The narrowed question and verified nearest baselines.

    Prompt to send
    Design a CPU pilot using a few equations with known ground truth and held-out shifts. Compare random sampling with an established disagreement method under equal measurement budgets. Specify how to count measurements until an invalid equation is detected, what false alarms to report, and when to stop. Keep hypotheses and expected outputs separate from measured results.

    Check and save: Freeze the equations, shifts, error threshold, budget, false-alarm rule and comparisons before coding. If the simple baseline matches the candidate method, reconsider the contribution before expanding the study. This example stops at pilot design.

Worked example 2 · Review and revision

From a reviewer concern to a verified fix

A survey manuscript claims that an intervention improves student performance. The reviewer checks what was actually measured, asks for a targeted revision, and checks the revised manuscript against the original issue.

The whole story in 6 pictures. Watch the status change from Not fixed to Partly fixed to Fixed ✓. The full prompts are further down.

  1. 1Give the AI the paper

    AskReview this paper and find the claim that matters most.

    ResultPaper + review instructions attached. Main claim found.

  2. 2Compare claim and evidenceProblem found

    AskThe abstract says: “The study tool improved quiz performance.”

    ResultBut the study only asked how prepared students felt. No quiz scores were collected.

  3. 3Ask for the smallest fix

    AskWhat can this kind of survey actually support?

    ResultNew wording: “Tool use was associated with higher self-reported preparation.” Must change in abstract, results, captions and conclusion.

  4. 4Check the first revisionPartly fixed

    AskThe abstract now says “self-reported preparation.”

    ResultBut the conclusion still says the tool improves quiz performance.

  5. 5Check the second revisionFixed ✓

    AskIs every place fixed now?

    ResultYes. All sections say “associated with”, and the Methods explain that students chose to use the tool.

  6. 6Match each claim to evidenceStill pending

    AskA test run shows the code works.

    ResultThat is not a result. Keep the result as “pending” until real outputs are checked.

Lesson: a fix only counts when every place in the paper is changed. Check again after each revision.

How a review issue gets closed

Does the revised evidence meet the original closure test?
No change or no evidenceOPEN

Keep the issue on the list and specify the missing change or evidence.

Some locations fixedPARTIAL

Point to the remaining unsupported sentence, analysis, or figure.

All required evidence checkedVERIFIED CLOSED

Record the revised passages and who checked them against the test.

  1. Prepare the review packet

    Give it: A numbered manuscript PDF, the review prompt, and Beihang Referee instructions. Add the supplement, outcome measures, or run artifacts if your claim depends on them.

    Prompt to send
    Use the attached review instructions. Read the manuscript and identify the claim most likely to change the paper's conclusion. List the files you could inspect. For each major issue give an evidence location, the reason it matters, the smallest adequate fix, and a closure test. Flag any page number, citation, or analysis you could not verify.

    Check and save: Save the input manuscript version and initial report. Download the practice excerpts and both revisions. For the mechanics of attaching files, follow the three-file practice walkthrough.

  2. Compare the claim with the evidence it needs

    Abstract · original

    “The study tool improved quiz performance.”

    Methods · original

    “Students reported whether they felt better prepared. Quiz scores were not collected. Students chose whether to use the tool.”

    Prompt to send
    Quote the exact claim and point to the outcome definition. What was measured? What would have to be measured or identified to support the stronger claim? Check whether the result is observational and whether the evidence really supports the review concern.

    Check and save: Open the Methods yourself. The outcome is self-reported preparation, and the groups are self-selected. Save issue R1 with both passages. This is a measurement problem and a causal interpretation problem.

  3. Ask for the smallest adequate fix

    Give it: R1, the original passages, and the Results wording that the underlying evidence supports.

    Prompt to send
    Suggest the minimum revision that preserves the supported finding. Give exact replacements for the abstract and conclusion. Then write a closure test that a fresh reviewer can apply to the abstract, results, figure captions, and conclusion. Explain what additional evidence would be needed if the authors want to retain the original claim.

    Check and save: For this teaching case, use “Tool use was associated with higher self-reported preparation in the surveyed class.” The original performance claim would require actual performance evidence. A causal claim would also require a design or credible identification strategy that supports it.

  4. Revise every location that carries the claim

    Abstract · revised

    “Tool use was associated with higher self-reported preparation.”

    Conclusion · still unchanged

    “The tool improves quiz performance.”

    Prompt to send
    Search the revised draft for all occurrences of the unsupported performance or causal claim, including paraphrases and figure captions. Return original wording, proposed wording, and section. Preserve numerical results and flag anything you cannot validate against the supplied evidence.

    Check and save: The abstract edit alone leaves R1 PARTIAL. Save the version and update the conclusion and any captions that repeat the unsupported claim.

  5. Re-review against the original issue

    Give it: The original report, the revised PDF, the author’s response, and the original R1 closure test. A second reader can check the passages independently.

    Prompt to send
    Verify each original concern against the revised manuscript. For R1 check the abstract, outcome definition, results, figures and captions, and conclusion. Quote the revised evidence. Mark OPEN, PARTIAL, or VERIFIED CLOSED, and list any location you could not check. A response letter alone is insufficient evidence of a change.
    Example revision-closure record
    IssueWhat the second reader findsStatus
    R1 · First revisionAbstract corrected. Conclusion still claims improved quiz performance.PARTIAL
    R1 · Second revisionAll checked sections describe an association with self-reported preparation. Methods disclose self-selection and the absence of quiz scores.VERIFIED CLOSED

  6. Check what the evidence can support

    Give it: Your test log, run outputs, and claim list when the manuscript makes computational or empirical claims.

    Prompt to send
    For each claim, identify whether the evidence is a synthetic software check, a measured study result, an independent reproduction, or pending. Cite the artifact you inspected. If only synthetic inputs were used, explain which software behavior was checked and which scientific claim still needs evidence.

    Check and save: A synthetic fixture can show that a reporting script runs. An empirical claim needs the corresponding study outputs. Keep pending claims open, even when the writing is improved.
